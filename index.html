How I work

I'm a backend developer working primarily with Laravel and MySQL, currently contributing as a volunteer developer on a team building an AI-powered Arabic study assistant. That project is where most of my recent hands-on work lives — onboarding onto an existing codebase, and structuring file uploads and business logic around a proper service/repository separation.

I like understanding the "why" behind a pattern before I use it — not just copying a solution, but knowing what problem it actually solves. That shows in how I approach new codebases: read the schema, read the relationships, understand the constraints, then write code that respects them.

Outside of core development, I've worked through Git internals, team branching workflows (feature → develop → main), and database design from the ground up — including full ERDs for multi-table schemas before a single line of backend code was written.

project_02

Driving License Management Platform

repo → demo →

A backend platform simulating a government agency's licensing system — replacing paper processes with a digital workflow for issuing, renewing, and managing driving licenses. It enforces real regulatory logic: category-specific age eligibility, sequential exam requirements (vision → written → practical) before issuance, exactly one active license per category per person, and automatic driver-record linking on first issuance. Blocked or expired licenses are correctly excluded from renewal and replacement flows, and every hold/release action is logged with the responsible user, date, and any fine paid — built for auditability, not just functionality.

Laravel PostgreSQL Role-based access Audit logging

project_03

Gaming Store — E-commerce API

repo → demo →

A Laravel API simulating a real online store, built to explore the parts of e-commerce that actually matter under the hood. Guests can browse and build a cart with no account, tracked via a guest_token; on login, the system decides whether to merge that cart into an existing one or attach it directly — handling both cases cleanly instead of just overwriting data. Checkout requires authentication, and prices are snapshotted at order creation so a later admin price change can never retroactively affect a placed order. Orders can be cancelled or returned with full status tracking.

Laravel REST API Guest tokens Cart merging
